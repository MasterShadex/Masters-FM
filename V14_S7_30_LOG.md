# SE5 cycle 1/3 -- origin gate misses PyWebView host

## SE5.1 Trigger

Operator FAIL at STEP 5 gate after live PyWebView test:

> FAIL: PyWebView preview iframe shows "Preview unavailable in standalone
> testing" message instead of loading the live overlay. The Stage 7.27 SE5
> isProductionContext() check (EXPECTED_SERVER_ORIGIN = 'http://127.0.0.1:4242')
> is incorrectly detecting PyWebView as non-production. Need to either widen
> the origin check to accept whatever origin PyWebView uses, OR replace the
> origin gate with a different production detection mechanism.

## SE5.2 Diagnosis

`src/customize.cs` line 188:
```csharp
webView.CoreWebView2.Navigate("http://localhost:4242/customize");
```

PyWebView/WebView2 host loads customize via **`localhost`** host on port
4242. Stage 7.27 SE5 fix hardcoded **`127.0.0.1`** as the only production
origin. Browsers (including WebView2) treat `localhost` and `127.0.0.1`
as **distinct origins** for same-origin policy purposes, so
`location.origin === 'http://127.0.0.1:4242'` returns false in PyWebView.

`isProductionContext()` returns false -> every server-side fetch
(`loadConfig`, `saveConfig`, `previewConfig`) short-circuits silently ->
preview iframe srcdoc placeholder shown -> Apply to OBS no-ops with the
`saveConfig skipped (not on real server.js origin; standalone test mode)`
informational log.

**Why Stage 7.29 smoke missed this:** Stage 7.29 STEP 6 smoke ran via
preview MCP at `localhost:8765` -- also a non-production origin (different
port). isProductionContext returned false there too, but that was the
desired behavior for the standalone test environment. The bug surfaces only
when the real PyWebView host opens customize at `localhost:4242` (which
SHOULD be production but isn't whitelisted).

## SE5.3 Fix shape

`src/customize.html` -- replace the hardcoded string constant with an
array of accepted production origins:

```javascript
// Before
const EXPECTED_SERVER_ORIGIN = 'http://127.0.0.1:4242';
function isProductionContext() {
    return location.origin === EXPECTED_SERVER_ORIGIN;
}

// After (Stage 7.30 SE5 strike 1/3)
const EXPECTED_SERVER_ORIGINS = [
    'http://127.0.0.1:4242',
    'http://localhost:4242'
];
function isProductionContext() {
    return EXPECTED_SERVER_ORIGINS.indexOf(location.origin) !== -1;
}
```

+11 / -2 lines. One constant + one function body. No other surface area
touched. Standalone mode preserved (any origin NOT in the allowlist still
falls into the standalone path).

Commit: `aa00dce Stage 7.30: SE5 FIX (strike 1/3) -- isProductionContext accepts localhost:4242 AND 127.0.0.1:4242 (PyWebView uses localhost host)`
