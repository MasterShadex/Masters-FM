### NO config GET endpoint

**Critical finding:** current customize.html does NOT load config from the server on init. Line 2674 starts `S` with `clampLayoutCanvas(deepMerge(DEFAULTS, {}))` -- always defaults, never a server fetch. User's saved customizations exist on disk (server-side) but aren't shown as "current state" when reopening customize. They have to be reloaded via Preset Manager.

### Iframe preview src is `/?preview=1`

Line 2216: `<iframe id="preview-frame" src="/?preview=1" ...>`. NOT a static `overlay.html` path -- the server.js routes `/?preview=1` to serve overlay in preview mode (presumably with SSE wired up).

### Live preview mechanism is SSE

Comment at line 2715: "the SSE pipe pushes the new config to the iframe and the iframe re-renders". So `/preview-config` POST broadcasts the config via SSE; the iframe subscribes and applies the values to its own DOM/CSS variables. customize.html does NOT inject CSS vars directly into the iframe contentDocument.

**Architecture implication for customize_v2.html:** the brief's `setMasterVar`/`setOverlayVar` approach (write to both `:root` and `iframe.contentDocument.documentElement`) WORKS in customize_v2's own preview iframe IF the iframe is same-origin. But the CANONICAL path used by current customize.html is to POST `/preview-config` and let the server's SSE broadcast handle it. For maximum compatibility we should use the canonical path (POST `/preview-config`) for live updates and ALSO set local `:root` for any same-page consumption.

### Reset to Defaults is client-side only

Lines 4530-4537: just `S = JSON.parse(JSON.stringify(DEFAULTS))` + `markDirty()` + `syncAll()` + `preview()`. No server reset endpoint. The user must subsequently click "Apply to OBS" to actually persist the reset to disk.

## S0.7 loadConfig + saveConfig + previewConfig API lock

```javascript
async function loadConfig() {
    // No canonical GET endpoint in current customize.html. Try a
    // defensive GET /get-overlay-config; on 404 fall back to empty.
    try {
        const r = await fetch('/get-overlay-config');
        if (!r.ok) return {};
        State.config = await r.json();
        return State.config;
    } catch { return {}; }
}

async function saveConfig() {
    // POST /save-overlay-config (matches current customize.html line 4494)
    try {
        const r = await fetch('/save-overlay-config', {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify(State.config)
        });
        if (!r.ok) throw new Error('HTTP ' + r.status);
        State.isDirty = false;
        return true;
    } catch (e) {
        console.error('saveConfig failed:', e);
        return false;
    }
}

async function previewConfig() {
    // POST /preview-config (matches current customize.html line 3429/4468);
    // server SSE-broadcasts to the preview iframe
    try {
        await fetch('/preview-config', {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify(State.config)
        });
    } catch { /* preview live-update; non-fatal if it fails */ }
}
```

## S0.8 setMasterVar + setOverlayVar lock

```javascript
// setMasterVar writes the 5 master CSS variables to BOTH:
//   1. customize_v2's own :root (for any same-page CSS that consumes it,
//      e.g. preview thumbnails if any)
//   2. iframe.contentDocument :root (same-origin write; if cross-origin
//      blocks it, the SSE pipe via previewConfig() handles propagation)
function setMasterVar(name, value) {
    document.documentElement.style.setProperty(name, String(value));
    const f = document.getElementById('preview-iframe');
    if (f && f.contentDocument && f.contentDocument.documentElement) {
        try { f.contentDocument.documentElement.style.setProperty(name, String(value)); }
        catch { /* cross-origin; SSE pipe will catch it */ }
    }
}

// setOverlayVar writes per-element CSS variables (NOT masters) to the
// iframe only (customize_v2 doesn't render the overlay's per-element
// styles in its own context, so no need to write to customize_v2 :root)
function setOverlayVar(name, value) {
    const f = document.getElementById('preview-iframe');
    if (f && f.contentDocument && f.contentDocument.documentElement) {
        try { f.contentDocument.documentElement.style.setProperty(name, String(value)); }
        catch { /* cross-origin; SSE pipe handles */ }
    }
}
```

Both helpers degrade gracefully when the iframe blocks contentDocument access (cross-origin restrictions). In that case the `previewConfig()` POST + server SSE broadcast is the canonical propagation path.
