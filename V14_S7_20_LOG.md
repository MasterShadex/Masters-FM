### S0.5.E Card root element selector (for Master Overall Size coordination)

**Critical finding:** `src/customize.html` line 1764 shows:

```html
<iframe id="preview-frame" src="/?preview=1" scrolling="no" title="Overlay preview" allow="microphone"></iframe>
```

The preview pane is an `<iframe>` loading `overlay.html` via `/?preview=1`. The "card" element being styled lives **inside** overlay.html's DOM (not customize.html's DOM). Customize.html cannot directly:
- Apply `transform: scale()` to the in-iframe card
- Add `.no-glow` / `.no-animations` classes to the in-iframe card root
- Read inside-iframe CSS variables

**Absolute rule 2 (NO TOUCHING `src/overlay.html`)** locks down this surface. Therefore:

- All 5 master controls' VISUAL preview effects can only be achieved IF AND ONLY IF overlay.html happens to already consume `--accent-master`, `--text-scale`, `--overall-scale`, `--glow-master-enabled`, `--animations-master-enabled` -- which it does not (verified by previous Stage 7.19 archive comparison; no such CSS variables in overlay.html's `:root`).

- Stage 7.20's masters will therefore be **wired-but-not-yet-functional in preview** until Stage 7.20.5 (optional, operator-commissioned) adds overlay.html consumption.

**Honest documentation per S12 mandate:** the Stage 7.20 UI delivers the controls + persistence + save/load contract. Stage 7.20.5 would deliver the visual functionality. Operator can decide post-PASS whether to commission 7.20.5 OR ship as-is (with documented limitation) OR jump to 7.21.

**Settings transmission path (already exists -- no change needed):** customize.html's existing save flow POSTs the entire `S` JS object to `/save-overlay-config` and `/preview-config`. The new master fields (`S.masters = { accentColor: ..., overallSize: ..., textSize: ..., glowEnabled: ..., animationsEnabled: ... }`) get serialized alongside everything else. Overlay.html receives the JSON but won't act on `S.masters` until 7.20.5 wires consumption. The contract is preserved.

## S0.7 Search bar spec (LOCKED)

### HTML structure (in `sidebar-header`, above Quick Settings section)

```html
<div class="search-bar-container">
    <input type="text" id="settings-search" placeholder="Find a setting..." aria-label="Search overlay settings" />
    <button class="search-clear" id="search-clear" aria-label="Clear search" type="button">×</button>
</div>
```

### Keyboard shortcut

- `keydown` on `document`: if `event.ctrlKey && event.key.toLowerCase() === 'f'` -> `event.preventDefault(); document.getElementById('settings-search').focus();`
- Scope: ONLY when the customize.html document has focus (not when a different window is foreground). Native browser scoping handles this -- the event listener is on customize.html's document.

### Search index (`data-search` attributes on every `.row` element)

Pattern per row (STEP 7 deliverable):
```html
<div class="row" data-search="<friendly label> | <old jargon label> | <synonym1> | <synonym2> | <section name>">
  ...
</div>
```

Example (STEP 4 of Stage 7.19 renamed "Spectrum Visualizer" -> "Audio bars"; "Loudness Boost" -> "Make quiet sounds louder"):
```html
<div class="row" data-search="make quiet sounds louder | loudness boost | autogain | compression | audio bars">
```

Rename map source: `V14_S7_19_LOG.md` STEPs 2-5 commit diffs (the rename pairs are captured there).

### Live filter behavior

- Empty input -> show everything normally (no classes added)
- Non-empty input -> debounce 80ms, lowercase match against each `.row[data-search]` value:
  - Matching rows: add `.row-highlighted`
  - Non-matching rows in sections that have at least 1 match: add `.row-dimmed`
  - Sections with zero matches: add `.section-hidden-by-search` to the parent `.sec` element (visually hides the entire section via `display: none`)
- Matched sections auto-expand if collapsed (force `.sec-body.open` class via JS)
- Ctrl+F always focuses + selects the search input

### Clear button

- Visible (`opacity: 1`) when input has non-empty value; faded otherwise
- Click clears input + dispatches the same filter logic (empty path: restore full view)
- Esc key on the input: clear + blur input

```css
/* Basic mode (default): advanced controls hidden */
.advanced-only { display: none; }

body.show-advanced .discovery-link { display: none; }
```

- localStorage key: `customize_show_advanced` (string `"true"` / `"false"`)

- Defensive: wrap localStorage read/write in try/catch (private browsing / localStorage disabled)
