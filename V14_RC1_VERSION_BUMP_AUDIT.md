### Csproj AssemblyVersion / FileVersion / InformationalVersion (NOT touched per minimal-change discipline)

Brief STEP 2.4 recommends:
- AssemblyVersion: 14.0.0.0
- FileVersion: 14.0.0.0
- InformationalVersion: 14.0.0-rc.1

Current state: all .NET 8 csprojs (`launcher.csproj`, `audio_spectrum.csproj`, `customize.csproj`, `server_dotnet.csproj`, `tray_native.csproj`) have `<GenerateAssemblyInfo>false</GenerateAssemblyInfo>`. This was an intentional Stage 1-5 decision to maintain parity with the legacy csc.exe build (which embeds no assembly metadata). Adding the version properties without flipping `GenerateAssemblyInfo=true` does nothing; flipping it adds assembly attributes that would change embedded binary metadata across all .NET 8 binaries.

**Decision:** keep `GenerateAssemblyInfo=false` for RC1. The user-facing version is in tray.ps1 (canonical), version.json (regenerated), and the HttpClient UA strings (manually bumped). Adding embedded assembly version metadata is a Stage 8 build-pipeline-cleanup item, not RC1-blocking. No csproj edits in this STEP 2.

`tray_launcher.cs` line 41-42 has its own `[assembly: AssemblyVersion("5.0.0.0")]` that ships embedded in `MastersFM_Tray.exe`. This is the tray host's own internal version (history of v1.9.9 -> v2.0.0 -> v5.0.0 evolution); NOT the app version. Leaving unchanged per directive 5 (tray.ps1 allowlist excludes tray_launcher.cs anyway -- different file -- but the principle of minimal change applies).
