**server.log post-install:** zero ERROR/WARN in last 200 lines.

**Root cause investigation (per SE5):**

1. `src/tray_csharp/ViewModels/AudioDeviceViewModel.cs` line 61: `public AudioDeviceInfo? SelectedDevice => _selectedDevice;` -- expression-bodied getter, NO setter. The property is genuinely read-only.
2. The error message indicates a TwoWay or OneWayToSource WPF binding targets this read-only property somewhere (likely in the Setup Wizard XAML hierarchy -- the error fires at "setup wizard show" specifically).
3. `git log --oneline -10 -- src/tray_csharp/ViewModels/AudioDeviceViewModel.cs src/tray_csharp/Dialogs/AudioDeviceWindow.xaml` returns commits ONLY from Stage 7.12 Batch A/B/C (`5487b7f`, `68322f7`, `b486369`, `6219108`, `e31f492`, `9d0b750`, `8890e83`, `6c10041`, `23c4c54`, `369f7cf`) -- all dated May 17 or earlier. The relevant rename-to-read-only happened during Stage 7.12 Batch A STEP 3 rev16 (commit `23c4c54`, "fully manual selection -- no SelectedItem bindings") which flipped SelectedDevice to read-only. The Setup Wizard XAML binding to SelectedDevice was apparently not updated alongside that rev16 change.
4. **Stage 7.19 SE3 commit diffs verified at every commit (STEPs 0-10) show ZERO WPF files touched.** The Stage 7.19 commit chain only modified `src/customize.html` (CSS + HTML rename/help/sub-header changes), `V14_S7_19_LOG.md`, and added `_archive/v14_customize_pre_redesign/customize.html`. No `.cs` or `.xaml` file in `src/tray_csharp/` was edited.
5. The Setup Wizard fires on every fresh install (new install = empty config = `welcome_seen_version` absent → wizard shows). The error has therefore been logged on **every install since May 17**: rc.3, Stage 7.13, 7.15, 7.16, 7.17, 7.18, 7.19. It was not surfaced at prior gates because the gate test instructions never exercised the Setup Wizard path; operator's gate tests focused on tray-menu visuals + functional checks of the customize panel + OBS overlay + start-on-login (Stage 7.18 Task A).

**Conclusion:** ONE new ERROR appears in the post-rebuild log, but its CAUSE is a pre-existing WPF binding bug from Stage 7.12 Batch A (commit `23c4c54`, 2026-05-17). Stage 7.19 did NOT introduce, modify, or expose this bug -- the bug fires on every tray bootstrap regardless of customize.html state.

**Operator authorized:** Treat as pre-existing, NOT a Stage 7.19 regression. Document in this log as a scope-expansion temptation parked per SE7. Proceed to S12.1 pre-gate checks and print operator gate.
