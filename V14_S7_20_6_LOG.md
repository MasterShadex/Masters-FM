### Verification (STEP 2)

Stage 7.20.5 STEP 7 + SE5 fix already handles the sentinel correctly in overlay.html:
- `R.setProperty('--<element>-color', 'var(--accent-master)')` writes the literal string
- CSS `color: var(--<element>-color, var(--accent-master))` resolves the chain to `--accent-master` (which itself is set by the master accent picker)
- Spectrum WebGL: line 3630 detects literal `var(--accent-master)` and substitutes the current master hex before passing RGB

Customize-side: theme apply (`applyTheme()` line 2383) deepMerges theme over DEFAULTS over S. With the sentinel as the theme's value, S.<element>.color becomes the literal string. The bindColor restore in syncAll reads S.<element>.color and writes it to the picker UI -- the existing picker handlers (which accept any string value) will accept this. The color INPUT (type="color") cannot DISPLAY a `var(--...)` string and will show the previous swatch; the hex text input shows the literal string. Stage 7.20 "Use accent" link already demonstrates this pattern works (the link writes the same string to the text input via dispatched input event).
