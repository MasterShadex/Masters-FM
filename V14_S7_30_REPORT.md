# SE5 cycle log (this stage)

## Strike 1/3 -- origin gate localhost vs 127.0.0.1 (FIXED INLINE)

**Trigger:** Operator FAIL at STEP 5 gate -- PyWebView preview iframe
showed standalone-mode placeholder; Apply to OBS silently no-op.

**Root cause:** `src/customize.cs` line 188 navigates to
`http://localhost:4242/customize`. Stage 7.27 SE5 fix hardcoded
`http://127.0.0.1:4242` as the only production origin. Browsers treat
`localhost` and `127.0.0.1` as DISTINCT origins. `isProductionContext()`
returned false in PyWebView -> server-side fetches short-circuited.

**Fix:** Replace string constant with `EXPECTED_SERVER_ORIGINS` array
accepting both `http://localhost:4242` and `http://127.0.0.1:4242`.
Commit `aa00dce`. Preserved in `customize_v2_archive.html` for Stage 7.30.1.

**Effect on customize.html SHA:** delta from V2_SHA (`FFAB016B59A5...`)
to `B14F634FE7189F7E...`. The "pure rename only" rule was relaxed via
this SE5 cycle. Operator authorized via FAIL diagnosis with prescribed
fix shape.

## Strike 2/3 -- FLAT State.config vs NESTED overlay.html shape (DIAGNOSED ONLY)

**Trigger:** Operator FAIL at re-gate after strike 1 fix landed --
control changes (slider/picker/toggle) do NOT propagate to OBS;
Apply-to-OBS save and Reset look "correct" only because overlay falls
back to its own DEFAULTS when it can't parse the flat payload.

**Root cause:** `State.config` is FLAT keyed by `c-*` ID (Stage 7.28
STEP 4 refactor). `previewConfig()` and `saveConfig()` POST flat blob.
overlay.html `applyConfig()` expects NESTED (e.g. `_cfg.card.backgroundTop`).
Shape mismatch -> every nested dereference returns undefined -> overlay
uses its DEFAULTS fallback -> user modifications never reach OBS.

**Why Stage 7.28 STEP 7 + Stage 7.29 STEP 6 smokes missed it:** both
smokes verified controlRows / themeOptions / masterBadges / supercat
counts via DOM queries on the customize panel itself. They never
tested that an actual control change propagates through previewConfig
-> SSE -> OBS overlay -> DOM update. The new round-trip surface was
not in the smoke matrix.

**Fix scope (DEFERRED to Stage 7.30.1):** A `CONTROL_NESTED_PATH` map
per c-* ID (~120 entries; same pattern as Stage 7.29 THEME_KEY_MAP but
for the full set) + a `flatToNested(State.config)` helper + apply in
saveConfig + previewConfig before POST. Operator directive: do NOT
manually invent 120 paths -- research legacy customize.html's
`applyConfig` / `buildConfigFromControls` / `syncAll` for the existing
nested-path contract and reuse.
