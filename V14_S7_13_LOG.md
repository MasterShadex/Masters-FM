### S0.4 Decision: Inter vs Segoe UI

**Decision: Segoe UI** (drop the Inter Google Fonts CDN at line 10).

Rationale:

1. **Match WPF dialogs.** The native dialogs (`AudioDeviceWindow`, `AppDialogStyle`, etc.) all render in Segoe UI via the system. Using Segoe UI in customize.html makes the two surfaces visually cohesive instead of two different families.
2. **No network dependency.** customize.html is served by the local server (`server.js`) and opens inside the WebView2 host that ships with the MSI. Removing the Google Fonts CDN means the page does not block on a network fetch when the user is offline or when DNS for `fonts.googleapis.com` is slow.
3. **No layout regression.** Inter and Segoe UI have very similar metrics at 13-14 px body sizes. The 4 px spacing rhythm + line-heights in `V14_S7_13_DESIGN_TOKENS.md` were tuned against Segoe UI in WPF -- using the same family in HTML keeps vertical rhythm consistent.
4. **The font stack is already in the v14 tokens.** STEP 2 will inject `--font-ui: 'Segoe UI', system-ui, -apple-system, sans-serif;` directly into `:root`.

Side effects:

- Line 10 (`<link href="https://fonts.googleapis.com/...">`) is removed in STEP 3.
- Line 39 (`font-family: 'Inter', system-ui, sans-serif;`) becomes `font-family: var(--font-ui);` in STEP 3.
- The inline SVG at line 553 has `font-family="'Inter',sans-serif"` -- STEP 3 retargets this to `'Segoe UI',sans-serif` to keep the FM logo glyph consistent.

### S6.2 Accent bar (signature v14 visual)

Added a 3-px animated gradient bar at the very top of the topbar:

**HTML** (1 line, inside `<header class="topbar">`):
```html
<div class="accent-bar"></div>
```

**CSS:**
```css
.accent-bar {
  position: absolute; top: 0; left: 0; right: 0;
  height: 3px;
  background: var(--accent-bar);                /* 3-stop brand-base/brand-glow/brand-base gradient */
  background-size: 200% 100%;
  animation: accent-drift 8s linear infinite;
  z-index: 1000;
  pointer-events: none;
}
@keyframes accent-drift {
  0%   { background-position:   0% 50%; }
  100% { background-position: 200% 50%; }
}
@media (prefers-reduced-motion: reduce) {
  .accent-bar { animation: none; }
}
```

Rationale:

- `position: absolute` inside the fixed-position `.topbar` means the topbar is the containing block. The bar spans full viewport width because the topbar already does (`left: 0; right: 0`).
- `z-index: 1000` is the brief's recommended value -- it sits above the topbar (`z-index: 200`) and any sidebar / dialog. Nothing in customize.html exceeds 1000 except the layout-edit handles inside the preview iframe, which never extend into the topbar.
- `pointer-events: none` so the bar never blocks clicks on the topbar's right-edge buttons (Preset Manager / Reset / Apply).
- The reduced-motion media query disables the drift loop for accessibility.

This is the only piece of customize.html that ABSOLUTE RULE 2 mentioned as a "wrapping `<div>` is acceptable" structural change. The brief's S6.3 specifies this addition explicitly.
