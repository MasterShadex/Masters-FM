## S8.FAIL.2 Root cause

Manual `dotnet publish` on tray project revealed:

```
MainWindow.xaml(62,59): error MC3000: 'An XML comment cannot contain '--',
and '-' cannot be the last character. Line 62, position 59.' XML is not valid.
ContextMenu.xaml(51,28): error MC3000: 'An XML comment cannot contain '--',
and '-' cannot be the last character. Line 51, position 28.' XML is not valid.
```

**The XML 1.0 spec (W3C, section 2.5) forbids `--` inside `<!-- ... -->` comments.** The string `--` may appear only as the closing delimiter `-->`; XML parsers reject `--` anywhere else in a comment, including legitimate text dashes.

**Conflict with em-dash hard constraint (project-wide rule):**
- The project's em-dash rule says use `--` (double-hyphen) instead of em-dash character `—` anywhere in source.
- BUT XML/XAML comments are an environment where `--` is forbidden by the parser regardless of intent.
- Stage 7.22 STEPs 3, 4 introduced new comments containing `--` (e.g., "IsHighlighted -- translucent accent tint", "CornerRadius 6 (was 4) -- softer Win11 feel"). These violated XML spec, breaking the XAML compile.

**Why prior stages didn't hit this:** Stage 7.7B (original ContextMenu.xaml + MainWindow.xaml authors) avoided `--` inside comments. The em-dash constraint is normally honored by replacing em-dashes in C# strings / JS / CSS, where `--` IS valid. XML comments are the one source-environment where the constraint can't be honored verbatim.

## S8.FAIL.3 Fix shape

Replace `--` inside XML comments with `:` or ` - ` (single hyphen with spaces). Per existing project precedent in customize.html STEP 7 / STEP 8 stages where `==` was used inside CSS comments (`/* renderer field removed == WebGL ... */`), I'll use ` - ` (single hyphen, restated meaning) since this is XML markup and `==` reads oddly in prose comments.

**Fix scope:**
- `src/tray_csharp/Theme/ContextMenu.xaml`: 4 instances on lines 51-55 (IsHighlighted/IsPressed/IsChecked/IsEnabled list)
- `src/tray_csharp/MainWindow.xaml`: 1-2 instances (line 40 area, line 62)
- Plus a defensive grep across both files for any remaining `--` inside comments

**Verification protocol:**
- After fix: run `dotnet build src/tray_csharp/MastersFM_Tray_v14.csproj -c Release -p:PublishReadyToRun=false` to confirm no error MC3000
- Then trigger full `_full_rebuild.ps1`
- Confirm new DLL `ProductVersion` reflects fix commit SHA
- Confirm new "[AutoStart] AutoStart forced ON (every install)" log line present in fresh overlay.log
