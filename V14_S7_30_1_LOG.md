## S0.3 Source-of-truth research

The canonical c-* ID -> nested S-path mapping is `initBindings()` in legacy
`src/customize.html` (line 3494-3847). Each `bindRange / bindColor /
bindToggle / bindSelect / bindText` call writes to a specific `S.path.to.value`.
`syncAll()` (line 4242-4435) is the inverse: reads `S.path.to.value` into the
DOM input. Together they define the round-trip mapping.

Server contract (verified in `src/server.js` lines 1143, 1382, 1478):
- `GET /overlay-config`     -> returns saved nested config
- `POST /preview-config`    -> live SSE broadcast (overlay.html receives nested)
- `POST /save-overlay-config` -> writes nested to disk + broadcasts as `event: overlay-config`

(Note: v2 archive currently uses `/get-overlay-config` which doesn't exist on
server.js. Stage 7.30.1 STEP 2 will correct that to `/overlay-config`.)

## S0.6 Special-case notes for STEP 1 implementation

1. **Arrays at leaves (`progressBar.fillColors[0..2]`):** the three c-prog-f{0,1,2} pickers each map to an array index. `flatToNested` must handle this -- represent as `['progressBar', 'fillColors', 0]` etc. (number at the leaf, not a string property).

2. **`c-border-colors` (border.colors as array of strings):** v2 stores this as a comma-separated string (colorList type). Translator should split on `,`, trim each, and write as array.

3. **`c-spec-sensitivity-reset` (button):** has no value to translate. Skip in `flatToNested`. Legacy code dispatches an `input` event on the sensitivity slider; the v2 bindButton currently no-ops -- Stage 7.30.1 STEP 3 will optionally wire the same dispatch behavior.

4. **`c-theme` (meta-state):** not part of the overlay-bound nested config. v2's `applyTheme()` already handles theme state through the SETTINGS_CONFIG flat path; the FLAT_TO_NESTED transform skips this id.

5. **Master sentinel ('var(--accent-master)'):** several entries default to the literal string `'var(--accent-master)'` (the 8 master-following pickers). The flat-to-nested transform passes the string through verbatim -- overlay.html's CSS engine resolves it via `--accent-master`.

6. **Layout dynamic nodes:** v2 SETTINGS_CONFIG only has the spectrum vis/lock pair; legacy iterates 8 nodes (albumArt / animatedBars / nowPlayingText / platformBadge / trackTitle / artistName / spectrum / progressBar). For this stage, just the spectrum pair is mapped. Stage 7.31 (or v14.1.0) can add the missing 7 nodes via a `rebuildLayoutEditor()`-equivalent.

## S3.1 previewConfig in-flight coalescing

Ported from legacy `customize.html` lines 4450-4479. First event always
fires immediately; subsequent events while a fetch is in-flight flip
`_previewPending = true`; the in-flight resolution checks and flushes
trailing state ONCE. Bounds server load during rapid slider drags
without lagging the first event.

```javascript
let _previewInFlight = false;
let _previewPending = false;
async function previewConfig() {
    if (!isProductionContext()) return;
    if (_previewInFlight) { _previewPending = true; return; }
    _previewInFlight = true;
    try { /* fetch /preview-config with flatToNested(State.config) */ }
    _previewInFlight = false;
    if (_previewPending) { _previewPending = false; previewConfig(); }
}
```
