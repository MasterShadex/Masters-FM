## S0.7 Hover decision LOCKED: neutral white tint

Two options weighed:
- (A) Neutral white tint `#22FFFFFF` -- matches Win11 default menu behavior, reads cleanly against pure-white label text, doesn't compete with accent identity.
- (B) Accent-tinted `#1A7C3AED` -- Stage 7.22 used this. Operator-pleased visually but the tradeoff: with high-contrast pure white text on near-black bg, an accent-tinted hover starts to compete with the brand identity already carried by the app name and check-marks.

**Decision: option A (neutral white tint `#22FFFFFF`).** Per brief operator-locked decision: "Hover state is neutral white tint, NOT accent purple (accent reserved for app name + check-marks)." Pressed state keeps `#33FFFFFF` (stronger tint). Accent retained ONLY at: app name in header (TrayMenuAccentBrush #7C3AED), check-mark stroke (TrayMenuAccentBrush).

## S0.8 Acrylic removal plan LOCKED

**Removal site:** `src/tray_csharp/MainWindow.xaml.cs` lines 95-115 (OnLoaded body's Acrylic gate block).

**Current behavior (Stage 7.22):**
```csharp
var acrylicSupported = WindowBackdrop.IsSupported(WindowBackdropType.Acrylic);
_logger.Log($"Acrylic supported={acrylicSupported}", "Tray");
if (acrylicSupported && NotifyIcon.ContextMenu != null)
{
    var cm = NotifyIcon.ContextMenu;
    cm.Opened += (_, _) =>
    {
        try
        {
            if (PresentationSource.FromVisual(cm) is HwndSource src)
            {
                WindowBackdrop.ApplyBackdrop(src.Handle, WindowBackdropType.Acrylic);
                cm.Background = Brushes.Transparent;
            }
        }
        catch (Exception ex)
        {
            _logger.LogErr("ContextMenu ApplyBackdrop(Acrylic)", ex, "Tray");
        }
    };
}
```

**Stage 7.23 action:** DELETE the entire block (21 lines). The XAML AppContextMenuStyle's `Background` will be updated to `TrayMenuBackgroundBrush` (#1A1A1A solid). No Acrylic override, no Transparent override at runtime. Crisp solid background unconditionally on all Windows versions.

**Side-effect cleanup:** Remove `using Wpf.Ui.Controls;` line if it's only used for WindowBackdrop (will verify via Grep at STEP 2).

**Infrastructure preservation:** `Wpf.Ui` NuGet package stays (referenced by Setup Wizard). Only the local application of acrylic to the tray context menu goes. SE7 vigilance: no refactoring of unrelated acrylic uses elsewhere in the codebase (if any).

**Log line cleanup:** `_logger.Log($"Acrylic supported={acrylicSupported}", "Tray");` gets removed with the block. The "Acrylic supported=False" / "=True" log line was diagnostic-only.
