# STEP 9 FAIL -- SE5 diagnosis (strike 1 / 3)

## S9.FAIL.1 Diagnosis

**Symptom:** Operator reports Master Accent Color (Quick Settings) does NOT visibly change accent-driven elements in OBS. All 4 other masters (Overall Size, Text Size, Glow, Animations) work correctly. Per-element wins test (Title blue stays blue when master goes red; "Use accent" link makes it red) PASSED.

**Root cause:** The Stage 7.20.5 STEP 2 fix (changing CSS fallbacks from hex to `var(--accent-master)`) only resolves the CSS chain when a per-element CSS variable is UNSET. In practice, customize.html ALWAYS sets per-element accent variables via `R.setProperty('--<element>-color', <hex>)` during applyConfig, populated from the user's saved config or theme defaults.

Walk-through:
1. Fresh install: customize.html's DEFAULTS object has factory accent values (`title.color: '#ffffff'`, `nowPlaying.color: '#c060ff'`, `bars.color: '#c060ff'`, etc., from the original brand palette + Default theme).
2. On Apply, customize.html POSTs S to `/save-overlay-config`. Server.js writes config.json. SSE broadcasts to overlay.
3. overlay.html applyConfig receives `cfg.title.color === '#ffffff'` (or whichever brand default).
4. STEP 7's master block (`R.setProperty('--accent-master', m.accentColor)`) correctly updates `--accent-master` to operator's chosen color (e.g., red).
5. **BUT** subsequent setProperty calls (24 sites at lines 1352, 1355, 1369, 1370, 1380, 1397, 1424, 1427, 1481-1489, 1946, 1970-1971, 1981, 1996, 2050, etc.) overwrite per-element CSS variables with the concrete hex from `_cfg.<element>.color`.
6. CSS resolves `color: var(--title-color, var(--accent-master))` -> `--title-color` is set inline to `'#ffffff'` -> CSS uses `#ffffff` -> the fallback to `var(--accent-master)` never triggers.

**Result:** Master accent has no visible effect on default-state / factory-themed elements. It only works when the user has explicitly clicked the "Use accent" link in customize.html (Stage 7.20 STEP 2), which writes the literal string `'var(--accent-master)'` to `S.<element>.color`. Then setProperty propagates that string to the CSS variable; CSS resolves the chain to master.

This was visible in operator's per-element-wins gate test step 6 (clicking "Use accent" on Title made it follow master) PASSING, while the master-by-default expectation (gate test step 4: "accent-driven elements should turn red") FAILING because no element starts in "follow master" mode.

**Operator's mental model:** Master should propagate to all accent elements out-of-box; per-element customization is the override.

**Current implementation reality:** Per-element values (theme-derived or saved) always override master; user must click "Use accent" per-element to opt in.
