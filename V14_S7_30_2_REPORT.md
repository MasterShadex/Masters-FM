# Standing rules (consolidated)

These rules apply to all future work that touches customize.html,
overlay.html, or the server.js wire contract.

## 1. Round-trip smoke pattern (introduced at Stage 7.30.1)

Any stage that changes the data shape between customize.html and
overlay.html MUST include a smoke test that verifies:

```
DOM input event -> State.config update -> wire-payload-shape verification
```

Stage 7.28 / 7.29 verified DOM counts only and missed the flat-vs-nested
bug all the way to Stage 7.30 PyWebView. Don't repeat that gap.

## 2. Fast-path file list (Stage 7.25.5)

`_full_rebuild.ps1` Test-IsHtmlOnlyChange whitelists `{src/customize.html,
src/overlay.html}`. Any HTML-only diff vs HEAD on these two files alone
takes the ~5-second fast path. Anything else falls through to cold rebuild.

If a new HTML asset is added that should benefit from the fast path,
extend the whitelist.

## 3. Origin allowlist (Stage 7.30 SE5 strike 1 / Stage 7.30.1 preserved)

`EXPECTED_SERVER_ORIGINS` in customize.html accepts BOTH
`http://127.0.0.1:4242` and `http://localhost:4242`. Browsers treat them
as distinct origins for same-origin policy. PyWebView/WebView2 uses
`localhost`; Python static testing uses `localhost:8765` (correctly NOT
in the allowlist). Future production-origin work must extend the array,
not replace it.

## 4. Standing test URL (added at Stage 7.28)

When testing customize_v2 / customize_v2_archive / new customize.html
standalone: `http://localhost:8765/<file>.html` via preview MCP
`customize_v2_static` config. The standalone short-circuits all
server-side fetches via `isProductionContext()` -- so the iframe shows
the srcdoc placeholder and Apply to OBS logs the origin-gate skip.

## 5. Pure-rename rule (introduced at Stage 7.30, re-affirmed at 7.30.2)

A "swap" stage performs file renames only. If either file needs a
content fix, that's a SEPARATE stage (SE5 separate-stage discipline).
Stage 7.30 strike 2/3 broke this rule and forced the cycle revert.
Stage 7.30.1 honoured it (separate stage for the translator). Stage
7.30.2 executes pure renames.

## 6. Operator-light gate (introduced at Stage 7.30)

For renames or large structural-but-content-preserving changes, the
operator-light gate is: Ruflo captures evidence (screenshots + console
queries + SHA256 + counts) and operator reviews the evidence + runs a
short focused smoke (~5-10 min) instead of hand-clicking through every
feature. Saves time and surfaces the critical-path failure modes.
