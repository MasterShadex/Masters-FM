## S4.4 Dispatcher + initBindings

```javascript
function bindControl(config) {
    switch (config.type) {
        case 'slider':    bindSlider(config); break;
        case 'color':     bindColor(config); break;
        case 'colorPair': bindColorPair(config); break;
        case 'toggle':    bindToggle(config); break;
        case 'select':    bindSelect(config); break;
        case 'text':      bindText(config); break;
        case 'number':    bindNumber(config); break;
        case 'colorList': bindColorList(config); break;
        case 'button':    bindButton(config); break;
        default: console.warn('[Stage 7.28] bindControl: unknown type', config.type, config.id);
    }
}

function initBindings() {
    for (const cfg of SETTINGS_CONFIG) bindControl(cfg);
}
```

# STEP 5 -- applyConfig data-driven + refreshControlValues + onResetDefaults refactor

## S5.1 applyConfig refactor

Replaces the 4-path hand-wired Stage 7.27 applyConfig with a 5-line iterator
over SETTINGS_CONFIG. For each entry, reads `State.config[cfg.id]` (falling
back to `cfg.default`) and delegates to `applyControlValue` (defined in
STEP 4). Identical CSS-var write semantics as the per-control binds, so
loadConfig + applyConfig at init produces the same overlay state as the
user manually setting every control to the loaded value.

## S5.2 refreshControlValues (new)

DOM-side mirror of `applyConfig`. Iterates SETTINGS_CONFIG and syncs each
input element to the current `State.config[id]` value without re-binding.
Per-type behaviour:

| Type | DOM update |
|---|---|
| slider / number | `$input.value = v; $display.textContent = v + unit` |
| colorPair | `$hex.value = v; $picker.value = v (if hex6)` |
| color | `$picker.value = v (if hex6)` |
| toggle | `$toggle.checked = Boolean(v)` |
| select / text / colorList | `$input.value = v` |
| button | no-op |

Used by onResetDefaults to reflect the freshly-defaulted State.config in the
UI without tearing down + re-attaching event listeners.

## S5.3 onResetDefaults refactor

Stage 7.27 reset cleared `State.config = {}` and called `initBindings()` to
re-attach listeners + read empty State.config -> fall back to HTML default
attribute values. That worked because the 4 hand-coded rows had inline
`value=...` attributes.

Stage 7.28 controls are now rendered from SETTINGS_CONFIG with no inline
defaults in the HTML (the create functions set initial values). So reset
must explicitly populate `State.config[id]` from `cfg.default` for every
entry, then call `refreshControlValues()` + `applyConfig()` + `previewConfig()`.
The iframe reload (production-context only) is the safety net for stale
CSS vars set by code paths outside SETTINGS_CONFIG.
